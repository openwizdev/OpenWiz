# 0.2.0 audit: what OpenWiz writes outside your project

Every file, setting and system change that OpenWiz's code and skills make outside the project repository, with a recommendation for each. The goal for 0.2.0 is that nothing lands outside the project without the user asking, and no third-party tool or service is on by default: each one is opt-in.

Audited on 2026-11-27, by reading the code at these commits:

| --- | --- | --- |

| `openwizdev/WizSkills` | `de29154e` | `main`. OpenWiz pins 0.5.0 (`cf2abfe1`); rows found only on `main` say so |
| `openwizdev/WizLoops` | `154c1d81` | `main` |

**In short:** 25 kinds of global write. 10 happen by default, with no yes of their own. 9 third-party tools or services are on by default. The worst three: the install copies about 20 skills with generic names into every coding agent on the computer, plus a plugin manifest and a `contracts` folder into each agent's own config folder (rows 2 and 3). The spec video quietly installs an npm package into `~/.cache` (row 17). The local driver keeps one full clone per builder run, forever (row 15). `install remove` cleans up none of the fleet-time rows.

Paths are written as the code writes them. `~` is the home folder. `<state>` is the install's state folder (by default `~/.local/lib/openwiz/state`). "Default" means it happens without its own yes; "opt-in" means a preview and the user's yes come first.

## The docs say less than the code does

- `docs/install.md:78` says the install writes only to its own folder, its state and the agents' skill folders. Rows 3, 5, 10 to 17 are missing, and so is the fact that `install remove` leaves them.

## Checked and clean

- **Shell rc files and `PATH`:** nothing edits `.bashrc`, `.zshrc` or `.profile`. `PATH` changes are for one command, or a line the person adds themselves.
- **Global git config:** OpenWiz writes none. The App token's credential helper is set per process through `GIT_CONFIG_COUNT` (WizSkills `skills/launch-fleet/scripts/github-app/agent-token.py:407`), and so is boat.dev's fetch. Only gh's own prompt can change `~/.gitconfig` (row 7).
- **Keychains:** read only. `kernel/driver-kit/hostkey.py:28` looks keys up with `security find-generic-password` or `secret-tool lookup`; the user adds them.
- **MCP servers:** none registered anywhere.
- **`/usr/local` and `/opt`:** never written. Only read, to find Tailscale (`tools/install/access/access.py:60`) and CloudRoom's cloud `room-cli`.
- **Global npm, pip or cargo installs:** none by code. Only CI and the hints in row 24.
- **Browser profiles:** none written. Sign-in opens the default browser; the video uses Playwright's own temporary profile.
- **Phone access** (`tools/install/access/access.py`) only checks a route the owner made, and records the result in `<state>`.
- **WizMarket** `check/check.py skill` runs a listing's check with a temporary `HOME` and no global git config.
