## The census check, resolved at cli-v3.0.75

Version: Cline CLI `cli-v3.0.75` (tag commit `06f0ec711ea417430d552b98e7911fdac6f495a1`, 2026-11-20). Every link below is pinned to that tag.

1. **Wake can't run headless.** `--id <session-id>` sets the startup target to the chat view and forces `interactive: true` with no prompt ([main.ts, `if (args.id !== undefined)`](https://github.com/cline/cline/blob/cli-v3.0.75/apps/cli/src/main.ts#L728-L746)). With `--json`, an interactive start is refused: `JSON output mode requires a prompt argument or piped stdin (interactive mode is unsupported)`, exit 1 ([main.ts](https://github.com/cline/cline/blob/cli-v3.0.75/apps/cli/src/main.ts#L794-L800)). Cline's own test is `forces chat view when resuming a session` ([main.test.ts](https://github.com/cline/cline/blob/cli-v3.0.75/apps/cli/src/main.test.ts#L1231-L1246)). So the census's `cline --json --id <session> "<msg>"` exits 1, and without `--json` it opens the terminal UI. The [CLI reference](https://github.com/cline/cline/blob/cli-v3.0.75/docs/cli/cli-reference.mdx) lists `--id` as "Resume an existing session by ID" and doesn't say it is interactive only.
2. **The JSON output carries no session id.** The reference's [JSON Output for Agent Runs](https://github.com/cline/cline/blob/cli-v3.0.75/docs/cli/cli-reference.mdx#json-output-for-agent-runs) lists `agent_event`, `hook_event`, `team_event`, `run_result` and `run_aborted`, and none of them holds a session id. `run_start` (only with `--verbose`) has a `sessionId` key, but it is read from the active session before the session starts, so a first run prints none ([run-agent.ts](https://github.com/cline/cline/blob/cli-v3.0.75/apps/cli/src/runtime/run-agent.ts#L49-L62), called before `sessionManager.start` at [L280](https://github.com/cline/cline/blob/cli-v3.0.75/apps/cli/src/runtime/run-agent.ts#L278-L281)). The run picks its id itself with `createSessionId()` ([L217](https://github.com/cline/cline/blob/cli-v3.0.75/apps/cli/src/runtime/run-agent.ts#L217)), and no flag lets the caller choose it.
3. **The hub.** A prompt run in yolo mode (the default with a prompt) forces the local backend: `forceLocalBackend: isYoloMode || config.sandbox === true` ([run-agent.ts](https://github.com/cline/cline/blob/cli-v3.0.75/apps/cli/src/runtime/run-agent.ts#L165-L179)), and `createCliCore` then passes no hub options ([session.ts](https://github.com/cline/cline/blob/cli-v3.0.75/apps/cli/src/session/session.ts#L37-L60)). Other modes use the environment's backend; `CLINE_SESSION_BACKEND_MODE=local` forces the local one ([reference, Environment Variables](https://github.com/cline/cline/blob/cli-v3.0.75/docs/cli/cli-reference.mdx#environment-variables)). So the session can live in the run's own process, and no hub starts. Only `--zen` needs the hub, and it refuses `CLINE_SESSION_BACKEND_MODE=local` ([run-zen.ts](https://github.com/cline/cline/blob/cli-v3.0.75/apps/cli/src/runtime/run-zen.ts#L40-L46)).
4. **Effort.** `--thinking <level>` takes `none|low|medium|high|xhigh` ([program.ts](https://github.com/cline/cline/blob/cli-v3.0.75/apps/cli/src/commands/program.ts#L39-L42); parsed at [L172-L192](https://github.com/cline/cline/blob/cli-v3.0.75/apps/cli/src/commands/program.ts#L172-L192)). Whether every provider honours it is not yet checked.

Items 1 and 2 leave no `wake` and no `session` form that the row contract allows, so this folder holds only the red run until #2530 is answered.
