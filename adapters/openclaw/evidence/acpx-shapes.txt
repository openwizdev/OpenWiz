# The driver's acpx calls given to the real acpx 0.22.0 (npm, MIT) in throwaway folders, with the built-in adapter
# in `--agent` replaced by a stand-in ACP agent (a short Python script that answers initialize, session/new,
# session/load, session/set_model and session/prompt, and logs its HOME and any auth variable it was given), so
# no harness, login or host is reached. "Your home" holds a synthetic ~/.acpx/config.json that maps claude to
# another command and sets an `auth` value; acpx runs with HOME set to the driver's own <state>/home.
# Each shape parses and works: the session opens, the prompt is queued and runs in the same session, cancel and
# close find it. The agent gets your HOME back and no auth variable; acpx refuses a bad policy and an unknown
# option as usage errors (exit 2; its help text after the second is cut). The control at the end shows why:
# with acpx's HOME left as your home, acpx copies your config's `auth` into the agent's environment.
$ HOME=<state>/home acpx --cwd <work> --agent 'env HOME=<your home> <stand-in agent>' --model m1 --auth-policy fail --permission-policy {"autoApprove":["read","search","edit","move","execute","think","fetch"],"autoDeny":["delete","switch_mode"],"defaultAction":"deny"} --non-interactive-permissions deny sessions new --name run-0123456789ab
