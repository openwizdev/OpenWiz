# The VPS session: sign in, then one command

For Jake, once, on the VPS. Spec #2474 ("VPS session files"). Everything below is yours to run: no agent signs in, exports a key or passes `--allow-cost` for you. This page holds names only, never a value.

## The session, in order

1. **Bootstrap** the free tools into `~/.local` (#2580): first `kernel/live-rig/vps/bootstrap.sh --dry-run` to read the plan, then `kernel/live-rig/vps/bootstrap.sh`. It never signs in or spends.
2. **Make the throwaway repository and ticket** as [the kit's throwaway-ticket setup](../../driver-kit/README.md#the-throwaway-ticket) says. Its `docs/agents/fleet.md` needs a `Record authors` row naming every account or app the hosts post as: your own login (Hermes, Pane, Factory), the account your Conductor agents comment as, and the account Cursor's agent comments as.
3. **Install Claude Code** for the Hermes and Pane runs (their harness is `claude`), with [its official install](https://code.claude.com/docs/en/setup): `curl -fsSL https://claude.ai/install.sh | bash`, then `claude --version` in a new shell. Run `claude`, then `/login`, and check it by hand with `claude auth status` (exit 0 when signed in; [CLI reference](https://code.claude.com/docs/en/cli-reference)). For Pane, check that its daemon finds `claude` on its own PATH: `runpane agents doctor --agent claude --repo active --json`.
4. **Sign in**, yourself: `gh auth login` first (every host needs it; [GitHub CLI manual](https://cli.github.com/manual/gh_auth_login)), then each host's row below. Export each key name in the shell you run step 5 from.
5. **Run the five checks once**, from the root of a clean checkout of `main`. Put your settings file (`{"repo": "OWNER/THROWAWAY", "ticket": N}`) and an output folder outside the checkout, and name them in the two variables. Every host config says `cost: paid`, so a host runs only when you name it with `--allow-cost`. Pass `--allow-cost` only for a host you have signed in to and checked by hand: the probes can't prove every sign-in (below). Leave out the hosts you didn't check:

   ```sh
   SETTINGS="$HOME/openwiz-live/settings.json"; OUT="$HOME/openwiz-live/out"
   python3 -I kernel/live-rig/heads.py --tickets kernel/live-rig/vps/live-tickets.json --hosts kernel/live-rig/vps/hosts --settings "$SETTINGS" --out "$OUT" --allow-cost Hermes --allow-cost Pane --allow-cost Factory --allow-cost Conductor --allow-cost Cursor --post
   ```

   Without `--post` the command still runs every allowed host's checks, so it can bill; it only skips posting (#2582). Run it once, with `--post`.

A host whose probe fails is skipped, `skipped <host>: <why>`; the rest still run.

**What the probes can't prove.** Each status probe is read-only and decides by its exit code. For **Hermes**, only GitHub is probed: Hermes has no status command whose exit code shows a sign-in, and the inner `claude` isn't probed. For **Pane**, `runpane repos list --json` passes whenever Pane's daemon is up, even when `claude` is signed out. For both, your hand checks in step 3 are the gate.

## One row per host

Each row starts with the host name its config gives (`hosts/<file>.json`, cited in Sources). "Status check" is what the rig runs before a run: read-only, output discarded, never a sign-in. The GitHub probe is `gh auth status --hostname github.com --active --no-refresh`: with `--no-refresh`, gh only reads the stored credential and never refreshes, replaces or removes it ([gh v2.105.0 `status.go`](https://github.com/cli/cli/blob/v2.105.0/pkg/cmd/auth/status/status.go#L540-L546)). "Bills" is whether one live turn bills beyond a plan you already have.
